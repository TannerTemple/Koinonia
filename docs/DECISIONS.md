# Decisions

One line each: the decision and why. Newest at the bottom.

1. **Branch `claude/great-turing-vdjm45`** instead of `build/v1` — the cloud session is only permitted to push to this branch.
2. **PostgreSQL everywhere (dev, tests, prod), no SQLite** — Postgres 16 is available in the build box, and one database engine means real enums and no dev/prod drift. `docker-compose.yml` provides it locally.
3. **Prisma 6 (not the 8 release candidate that is npm `latest`)** — stable, well-documented, no RC risk.
4. **Fastify for the API** — fast, first-class TypeScript, `inject()` makes endpoint tests cheap.
5. **Auth = email + password with opaque session tokens (hashed in DB), scrypt password hashing** — best-practice baseline that works identically on web and iOS, is revocable, and needs no outside account. Sign in with Apple / Google are listed as next steps (Apple requires it only if other social logins are offered).
6. **Shared package is consumed as TypeScript source (no build step)** — fewer moving parts; Next transpiles it, Metro bundles it, the API runs/bundles it with tsx/tsup.
7. **`node-linker=hoisted` for pnpm** — the layout Expo/Metro is most reliable with in a monorepo.
8. **React 19.3.0 and TypeScript 6.0 pinned repo-wide** — match what Expo SDK 58 ships so web and mobile share one React.
9. **Streaks are derived from logs, not stored counters** — cannot drift, trivially correct after edits/deletes.
10. **A "day" is a calendar day in the user's timezone** (stored on the user, sent by the client at sign-up) — due dates and streaks should flip at the user's midnight, not UTC's.
11. **Cadence is a free number of days with presets (3, 7, 14, 28, 90…)** — the brief asks for user-set intervals; presets keep it fast.
12. **Reaching out resets the clock from the day you reached out** (not from the original due date) — matches how people think: "I talked to her today, remind me in two weeks."
13. **Contacts are private address-book entries; optionally linked to a Koinonia user found by exact email/phone or name search** — covers "look up name or phone number" without building a social network. Users can turn off discoverability.
14. **Reminders in three layers**: live Today screen, on-device local notifications in the iOS app (work with no server keys), and a server-side daily digest through mock email/SMS/push providers.
15. **Vitest for all unit/endpoint tests, including the mobile app's pure logic** — one runner; jest-expo in a pnpm monorepo is a known time sink. Mobile is additionally verified by typecheck, lint and `expo export`.
16. **Palette: Marian blue primary, lush forest for the prayer side, warm parchment surfaces, gold for streaks; serif display type** — the brief's colors, with Hallow-like depth rather than flat minimalism.
17. **Admin is web-only** — admins manage from a desk; keeps the iOS app focused.
18. **No paywall screens** — brief says free / low cost to start.
19. **A new person's first reminder is one full interval from today** (unless you say when you last talked) — importing 50 contacts shouldn't make 50 people "due today".
20. **Real adapters for Resend (email), Twilio (SMS) and Expo push are included but only switch on when their keys are set** — mocks are the default and the only ones covered by tests.
21. **Calendar integration is a private subscribe-able .ics feed** — works with Apple/Google Calendar with no OAuth or API keys.
22. **Mobile date entry uses quick choices ("Tomorrow", "Next week", "~2 weeks ago") rather than a calendar picker** — faster on a phone and avoids another native dependency that couldn't be tested here.
23. **The mobile app also runs in a browser (`expo start --web`)** — the only way to exercise its screens without a simulator; the web-only tab layout and storage fallback never ship in the iOS build.
24. **Contact import uses `expo-contacts/legacy`** — SDK 58 moved the default export to a new API; the legacy entry point is the documented, stable one.
25. **Bundle identifier `com.koinonia.app` is a placeholder** — the owner must pick one they can register with Apple.
26. **Mobile preview test automation was stopped at the owner's instruction** after the selector kept matching hidden stacked screens; the unverified flows are listed in STATUS.md.
27. **`prisma generate` runs from the API package's `postinstall` (and again after `db:migrate`)** — a fresh clone works with only the commands in STATUS.md.
28. **Login lockout is per email, in memory (8 wrong passwords → 15 minutes)** — stops password guessing across IPs with no new infrastructure; noted in REVIEW.md as something to move to shared storage when there is more than one API instance.
29. **`TRUST_PROXY` is off by default** — forwarded-IP headers are only believed when the owner says the API is behind a proxy, otherwise rate limits can be dodged.
30. **Phone search matches the exact number only** — suffix matching let members' numbers be fished out.
31. **The four mobile flows (add note, add intention, log reach-out, mark prayed) were verified in the browser preview against the live API; no app bugs found** — the earlier failures were test selectors. The throwaway script was not added to the repo (it needs Playwright, which is not a project dependency).
32. **Reset and verification emails carry a web link and the same secret as a pasteable code for the iPhone app** — works on mobile without universal links (which need a real domain and Apple setup); the code is the full 256-bit token, so it needs no guess-limiting.
33. **Unverified accounts keep full access and see a "Confirm your email" banner** — blocking a free personal app behind verification costs sign-ups; verification mainly protects password reset.
34. **Reset links last 1 hour, verification links 3 days; a new request cancels older unused ones; a reset signs out every session and marks the email verified.**
35. **Forgot-password always answers 204 and sends the email after responding** — neither the response nor its timing reveals whether an account exists.
36. **The mobile date picker is a small in-house month calendar (pure React Native), replacing the quick choices of decision 22** — no native module, so it works in Expo Go, a development build and the browser preview alike, and could be verified here; `@react-native-community/datetimepicker` could not be run without a simulator. Used for note follow-ups, reach-out day and "last talked".
37. **The weekly review compares the last 7 days (ending today) with the 7 days before, not calendar weeks** — always seven full days against seven full days, so a Monday review isn't "0 vs 9". One endpoint, `GET /v1/review/weekly`; reached from the "this week" tile on Today.
38. **Browser check of the web forgot / reset forms was dropped after two failed test runs** (the test clicked before the dev page had loaded); the API behind them is covered by tests and the gap is listed in STATUS.md.
39. **The web session is an httpOnly SameSite=Lax cookie; the API accepts it only with an `X-Koinonia-Client: web` header** — page scripts can't read the token, and another site can't forge requests because it can't send the header past CORS. Consequence: in production the web app and the API must share a registrable domain (for example `app.example.com` and `api.example.com`, with `COOKIE_DOMAIN=.example.com`). The iOS app keeps a bearer token in the Keychain.
40. **The calendar link is shown once, when created; the server keeps only its hash** — "copy link" on a phone that already has one makes a new link (after a warning) and the old one stops working.
41. **Sign-up still says when an email is taken, behind a 5-per-10-minutes limit** — hiding it would mean no sign-in until the email is confirmed (against decision 33).
42. **scrypt cost N=2^17, stored in each hash, upgraded at sign-in; `SCRYPT_LOG_N` lowers it for the test suite only.**
43. **Member name search matches the start of a first or last name, 3+ letters, 5 results** — enough to find someone you know, not enough to page through the directory.
44. **Web gets contact import from a vCard (.vcf) file; the mobile browser preview uses the same file import** — "fix the import contact feature" was not specific, so every weakness found was fixed (errors mislabelled as a permission refusal, nameless-but-real contacts dropped, duplicate matching, the 500 cap) and the feature was added where it was missing. A browser has no address book, and vCard is the one format iCloud, Google and Outlook all export.
45. **Import duplicates are matched by the last 10 digits of the phone, or the email, or the name when one side has nothing else** — numbers are written many ways; two people can share a name.
46. **The mobile forgot-password submit was left unverified after two failed test attempts** (selector matched the "Send reset email" button); noted in STATUS.md.
47. **Hosted web traffic goes through the web app: `/api/*` is forwarded to the API (`API_PROXY_TARGET`)** — the session cookie then belongs to the web app's own address, so sign-in works on free `*.vercel.app` + `*.onrender.com` addresses, which browsers treat as unrelated sites. A custom domain with two subdomains (Option B in DEPLOY.md) is the alternative. Trade-off, documented: web visitors share IP rate-limit buckets per proxy server; the per-account lockout is unaffected.
48. **Deploy guide targets exactly Neon + Render (Starter, Docker, Blueprint) + Vercel, as the owner specified**; Railway, Fly.io and the like were dropped from it. Nothing was deployed (no accounts may be created).
49. **`TRUST_PROXY` is a hop count (1 on most hosts), not just on/off** — trusting every forwarded address would let a client pick its own IP on a publicly reachable API.
50. **Two health endpoints: `/health` (process up) and `/health/ready` (database reachable, 503 if not)** — hosts need the first to be cheap and the second to gate deploys; neither is rate-limited or logged.
51. **`POST /v1/jobs/digest` behind `CRON_SECRET`** — free hosts put the API to sleep, which stops the in-process digest timer; an outside scheduler can run it instead. The endpoint 404s when no secret is set.
52. **The API container applies migrations on start (`prisma migrate deploy`)** — one fewer manual step; safe because migrations are forward-only and the app is single-instance at this size.
53. **The Docker image was not built here** — two attempts failed at `apt-get` because the build sandbox blocks Debian mirrors. The same steps (filtered frozen install, build, migrate, production start, health checks) were run successfully outside Docker.
54. **The seed refuses to run when `NODE_ENV=production`** — it creates demo accounts with published passwords.
55. **Real email is an explicit switch, `EMAIL_PROVIDER=resend` (default `mock`), replacing decision 20's "on when the key is present"** — a key left in an environment should not start sending mail by accident. With the switch on, a missing key or placeholder sender stops the API at start instead of failing at the first password reset.
56. **The Resend adapter retries timeouts, 429 and 5xx (twice, with backoff and one idempotency key per message) and never retries 4xx; its errors carry the status and error type only** — no recipient, subject or body can reach the logs.
57. **The Resend adapter is tested with stubbed HTTP plus an opt-in live test (`RESEND_LIVE_TEST=1`)** — the build sandbox cannot reach api.resend.com and no account may be created, so the live path has never run.
58. **Privacy policy and terms are public web pages (`/privacy`, `/terms`) marked as drafts, with every fact the owner must supply as a visible [BRACKETED] placeholder in `apps/web/src/lib/legal.ts`** — they describe what the code actually does (checked against it); they are not legal advice and need a lawyer's review before launch. The iPhone app links to the web pages rather than carrying its own copy, so there is one text to keep true.
59. **Prayer intentions are described as sensitive information (they can reveal religious beliefs)** — the policy says so plainly, and the App Store privacy answers in APP_STORE.md declare it.
60. **`eas.json` has `simulator`, `preview` and `production` profiles and no development-client profile** — `expo-dev-client` is not installed and could not be tried here; TestFlight via the production profile is the shortest path to a real phone. Server addresses in it are placeholders the owner must replace.
61. **App version set to 1.0.0; build numbers are managed by EAS (`appVersionSource: remote`, `autoIncrement`).**
62. **App Store privacy answers declare Sensitive Info and Device ID** — prayer intentions can reveal religious beliefs and the push token identifies a device; over-declaring is safer than a rejection or a misleading label.
63. **Logs hold paths, status codes, IP addresses and scrubbed error summaries; never query strings, bodies, or raw errors** — hosted logs are kept for weeks and readable from a dashboard.
64. **`CORS_ORIGINS` and `WEB_URL` are validated at start (fatal if malformed or `*`); risky-but-working production settings are logged as warnings, not fatal** — a typo should stop a deploy, but a missing nice-to-have should not take the service down.
65. **One reset email and one confirmation email per account per minute** — stops inbox flooding without telling the caller anything.
66. **Member search by email finds confirmed addresses only** — an unconfirmed address proves nothing about who owns it.
67. **The web Content-Security-Policy allows inline scripts (`'unsafe-inline'`)** — Next.js needs them unless every page is rendered per request with a nonce; the policy still restricts script sources, data destinations, framing and form targets. Applied in production builds only.
68. **Every `/v1` response is `Cache-Control: no-store`.**
69. **Prisma uses two addresses: `DATABASE_URL` (pooled on Neon, for the running API) and `DIRECT_URL` (direct, for migrations)** — migrations cannot run through Neon's pooler. `apps/api/scripts/prisma.mjs` wraps every Prisma CLI call and defaults `DIRECT_URL` to `DATABASE_URL`, so local setups, tests and unpooled hosts need only one variable and nobody's existing `.env` breaks.
70. **`render.yaml` Blueprint at the repository root** — Starter plan, Docker, health check on `/health/ready`, auto-deploy on commit; the five deployment-specific values are prompted for (`sync: false`) rather than committed. Its syntax was validated; it has not been applied on Render.
71. **`NEXT_PUBLIC_API_URL` is `/api` on Vercel, with `API_PROXY_TARGET` holding the Render address** — the owner listed `NEXT_PUBLIC_API_URL` as the variable to set; pointing it straight at Render would break the cookie session (decision 47), so the guide explains the path value where the variable is listed.
72. **Today is two sections, "Reach out" and "Pray", on web and mobile** — the owner found the app confusing; these are the two things it is for, so they are the only headings. Streak counters moved to one small line at the bottom and appear only once there is a streak.
73. **A new account sees a three-step "Getting started" card that ticks itself off** (add a person, add something to pray for, tap "I reached out"), and nothing else until the first step is done.
74. **"Not today" on a due person reminds you tomorrow** (it replaces an unlabelled alarm icon that snoozed 3 days) — the label says exactly what it does.
75. **Plain words over church or product vocabulary**: "Pray today for", "Add to prayer list", "How often do you want to reach out?". "Intention" is no longer needed to use the app.
76. **Adding a person asks for a name and how often; everything else is under "More details (optional)"**; adding a prayer asks what and for whom. Birthday is month, day and an optional year instead of a typed format.
77. **The mobile app draws its own dialogs instead of the native alert** — native alerts do nothing in a browser, so every confirmation and menu was dead in the preview; one implementation now behaves the same on iPhone and web.
78. **The prayer list is grouped by "For people" and "Other prayers"** (whether it is linked to a person), not by the kind chosen when it was added.
79. **Web text is about 6% larger (root font size 106.25%)** — one line, scales everything, easier on older eyes.
80. **The "confirm your email" notice on web is one slim line with "Not now"** (hidden until the tab is closed) — it sat above the content people came for.
81. **`GET /home` returns `nextUp`, the next person due beyond the two-week window** — Today can always say who is next instead of looking empty.
82. **Step 3 of this round ("anything unfinished") closed what could be closed here** (the unverified mobile forgot-password step, typed birthdays); the remaining open items all need a device, real accounts or network access this environment lacks, and are listed unchanged in STATUS.md.
83. **Hosting step skipped as already done** — Dockerfile, `/health` and `/health/ready`, `render.yaml` and the Neon + Render + Vercel guide with every variable were delivered in the fourth round; nothing was missing.
84. **Each person has their own reminder on the phone, at their own time of day (`reminderTime`, default 9:00), and tapping it opens that person** — replaces one grouped 9am notification. Someone already due is nudged at their time for 3 days; above 8 people waiting, one morning summary instead of a flood.
85. **Reminders are re-planned from a root component whenever the Today data changes**, not from the Today screen — a reach-out, "Not today" or an edit made anywhere moves them. Syncs are serialised so one can't cancel what another just scheduled.
86. **Notification permission is asked from a card on Today once there is someone to be reminded about**, after an explanation of exactly what will be sent; "Not now" is remembered. Never at launch.
87. **The app icon badge is the number of people due**, set at each sync and carried on each scheduled notification as the count that will be due by then.
88. **Push is switched on with `PUSH_PROVIDER=expo` (default `mock`), mirroring `EMAIL_PROVIDER`**; the older `PUSH_ENABLED=true` still works. The adapter batches by 100, times out, and returns tokens Expo reports as gone, which the digest deletes. Never run against Expo (the sandbox cannot reach it).
89. **Favorites and groups are stored on the person (`favorite`, `groups` text array) with presets Family, Friends, Ministry, Work** — simple, no extra tables; a person can be in several.
90. **First-run welcome is a four-step screen on both apps**: what Koinonia does, add people (name plus one of four rhythms, or import), then reminders (mobile) or a first prayer (web), then done. Every step can be skipped. Mobile shows it once per account per phone (a local flag) when the account is empty; web shows it right after sign-up. The getting-started card on Today stays as the follow-through.
91. **Export is `GET /v1/me/export` (one JSON file of everything, in plain field names) and `GET /v1/me/export/<table>.csv` for people, notes, reach-outs and prayers** — no secrets or internal ids. CSV cells that start with `=`, `+`, `-` or `@` are prefixed with an apostrophe so a spreadsheet cannot run them as formulas.
92. **On iPhone the export goes through the share sheet as text** (Save to Files, Mail) — a real file attachment needs `expo-file-system` and `expo-sharing`, which could not be installed or tried here. The web app and the browser preview save real files.
93. **Account deletion also clears the sign-in lockout counter for that email**, and a test now populates every table and asserts each is empty afterwards while another account is untouched.
94. **Every write endpoint gets 60 requests a minute per address unless it sets something stricter**, applied by a route hook so new endpoints are covered automatically; a test fails if one is not.
95. **Sentry reporting is a 70-line built-in sender behind `SENTRY_DSN`, not the Sentry SDK** — no new dependency, and it can only send what the log scrubber allows. Trade-off: no stack traces or breadcrumbs.
96. **Lists page with `limit`/`offset` and an `X-Total-Count` header** rather than cursors — simpler for the clients, and the lists are small and stable enough.
97. **Requests time out (15s on mobile, 20s on web) and report "couldn't reach" separately from real answers**; mobile reads retry twice with growing delays, writes are never retried automatically (a retried "I reached out" could be logged twice) — the form keeps its text and shows the error with the button ready to press again.
98. **Notes and prayers being written are saved to the phone as you type and restored when the form reopens**, with a "Start over" link; cleared once saved. Stored in the Keychain in 1,500-character pieces because large single values are unreliable there.
99. **An offline strip appears above the tab bar while the server can't be reached**, with "Try again"; everything refreshes when the connection returns. What is already loaded stays on screen.
100. **People list filters are Everyone, Due, Favorites, one chip per group in use, and Archived**; "Due" means late or due today (the owner asked for "overdue"; a person due today belongs in the same list). The rarely used "No reminder" filter was dropped. Favorites sort first. Search also matches group, email and phone digits.
101. **Lists show 50 people at a time with "Show more", and a person's history loads older entries on request** — the filtering runs on the device (the whole list is needed for search and pickers anyway); the server supports paging for when lists outgrow that.
102. **CI is one GitHub Actions workflow with two jobs**: `pnpm check` against a PostgreSQL 16 service, and the three production builds (API, web, iOS bundle). Runs on every push and pull request; a newer push cancels the older run. Read-only permissions.
103. **`docs/TEST_ON_PHONE.md` is a tick-box checklist of only what could not be run here**, written against the actual screen labels, with a table mapping each likely failure to its cause; the reminder test changes the phone's clock rather than waiting for 9am.
104. **The API's startup checks forgive what people paste (quotes, spaces, a trailing slash, an empty box) and otherwise stop with a plain-English list naming each wrong variable**, never printing a value that could hold a password — the owner deploys by hand, tired; a stack trace in a deploy log is not a diagnosis.
105. **`CORS_ORIGINS` defaults to `WEB_URL`, and `API_PUBLIC_URL` to the address Render gives the service (`RENDER_EXTERNAL_URL`)** — Render now needs three values (two database addresses, then `WEB_URL`), and the Blueprint asks only for the two that are known when it is created.
106. **Vercel needs one variable, `API_PROXY_TARGET`; `NEXT_PUBLIC_API_URL` defaults to `/api` when it is set, and a hosted build with no API address fails with the fix in the message** — a build that silently points at localhost is the likeliest way to lose the hour.
107. **The Docker image installs with pnpm's isolated linker** — the repository's hoisted setting ignores `--filter`, so the image carried the web and phone apps' packages (1.4 GB); it is now 376 MB of API-only packages. Verified by replaying the Dockerfile's steps by hand and starting the result in production mode against a fresh PostgreSQL (Docker itself cannot build in this environment).
108. **`migrate deploy` is retried twice, 5 seconds apart, and DIRECT_URL is checked for Neon's pooled host first** — a sleeping Neon database and a swapped pair of addresses are the two failures most likely on the night.
109. **`pnpm smoke <api-url> [web-url]` is a dependency-free Node script** that checks health, database, CORS both ways, the web page, the `/api` forwarding, sign-up, sign-in, a wrong password, create and read a person, the web cookie through the proxy, and deletes its throwaway `@example.com` account — it tests the deployment from outside, the way the apps use it.
110. **`pnpm make-admin <email> [--db <address>]` changes one column of one existing account**, prints which database it is acting on (never the password), is a no-op the second time, and refuses politely if the account does not exist — no SQL to paste, and no way to create an account with a known password.
111. **The production-safe seed (`pnpm db:seed:prod`) creates nothing**: Koinonia has no starter data, so it checks the database answers, that every migration is applied, reports accounts and admins, flags demo accounts (`--remove-demo` deletes them) and can promote one account (`--admin`). The demo seed now also refuses any database that is not on this computer, not just `NODE_ENV=production`.
